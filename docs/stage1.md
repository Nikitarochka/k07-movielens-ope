# Этап 1 — оценщик и базовая ошибка (к 24 ноября)

## Задача, цель и прокси

Реальная прикладная цель — рекомендовать пользователю подходящий фильм.
В этом контролируемом эксперименте её прокси — индикатор исходной оценки
MovieLens `Rating >= 4`. Он не измеряет причинный эффект рекомендации,
не учитывает неоценённые фильмы и не является вероятностью реального клика.

Объект аудита — WIS, оценивающий среднюю прокси-награду фиксированной целевой
политики по моделируемому логу другой политики. Проверяем, насколько близка
оценка к точно вычислимому эталону. Простая базовая линия — средняя награда
в логе без поправки на политику; это намеренно наивная оценка целевой ценности.

## Данные и собственный набор аудита

Использован ранее зафиксированный K07-ML1M-25to34-v1: 1 696 пользователей,
383 928 оценок. Все 150 контрольных пользователей исключены из подсчёта
популярности: она вычисляется только по оставшимся 1 546 пользователям.
Для каждого контрольного пользователя фиксированы 20 уже оценённых фильмов.
Их сортировка по `(число оценок в разработочной части, MovieID)` не использует
контрольные значения Rating. Непопулярные первые пять фильмов — целевые,
популярные последние пять — предпочтения логирующей политики.

Сформированы 150 собственных задач аудита, описанных в `audit_tasks.jsonl`:
индекс задачи, пользователь, исходные строки 20 фильмов, целевые/популярные
индексы и точная ценность. Генератор создаёт для этих задач собственные логи.
Это производные контрольные задачи, а не новые реальные оценки пользователей.

Целевая политика равномерна среди пяти целевых фильмов. Логирующая политика:
`mu(a|u) = epsilon/20 + (1-epsilon) * I[a входит в популярные пять]/5`.
Основной аудит этапа 1 использует только **epsilon = 0.5**. Вероятность целевого
действия — 0.025, вероятность любого целевого события — 0.125; поддержка есть.
Точный эталон по равновзвешенным пользователям: **357 / 750 = 0.476**.

## Протокол и неопределённость

Один лог — 100 независимых действий с возвращением для каждого из 150 пользователей:
15 000 событий. Проведены 10 технических пилотных повторений и 500 основных.
Пилот не входит в метрики. Все параметры сохранены в `configs/stage1.json`.
Пилот и основной эксперимент используют разные ветви SeedSequence; в runs.csv
записан spawn_key, который вместе с корневым seed однозначно задаёт запуск.

WIS = sum(w*r)/sum(w), где w = pi/mu. При нулевой сумме весов результат
не определён, а не равен нулю. ESS = sum(w)^2/sum(w^2).
В данном дизайне все ненулевые веса равны 8: WIS также равен средней награде
целевых событий, ESS — их количеству. Это отдельно проверено в пилоте и тестах.

Для каждой оценки сохранён приближённый нормальный 95%-интервал. Стандартная
ошибка рассчитана с учётом фиксированных 100 событий в каждом пользовательском
слое. Для WIS используется delta-method: остаток z = w*(r-WIS), оценка дисперсии
равна `sum_u(n_u * sample_variance(z_u)) / sum(w)^2`. Для naive применяется та же
стратификация без весов. Интервалы не обрезаются до [0,1].
RMSE и средняя ошибка имеют отдельные 95%-bootstrap-интервалы по 500 независимым
основным запускам (2 000 повторных выборок). Эти интервалы описывают Monte Carlo
неопределённость для фиксированных 150 задач, а не неопределённость всей популяции.

## Базовые результаты

| Показатель | WIS | Наивная средняя |
|---|---:|---:|
| Средняя оценка | 0.476180 | 0.646722 |
| Средняя ошибка относительно 0.476 | +0.000180 | +0.170722 |
| 95% интервал средней ошибки | [-0.000796; 0.001167] | [0.170418; 0.171033] |
| RMSE | 0.011333 | 0.170759 |
| 95% интервал RMSE | [0.010669; 0.011982] | [0.170455; 0.171069] |
| Покрытие эталона 95%-интервалами отдельных логов | 94.4% | 0% |
| Доля неопределённых оценок | 0% | 0% |

Средний ESS WIS — 1 875.19 при 15 000 строках лога. При хорошем покрытии WIS
в этом эксперименте близок к эталону; наивная средняя систематически завышает
целевую ценность, поскольку оценивает результат другой политики. Узкие интервалы
наивной средней относятся к среднему её логирующей политики и не устраняют это
смещение относительно целевой политики. Даже WIS имеет случайные ошибки отдельных
логов: пять наибольших абсолютных ошибок сохранены в `error_cases.csv` вместе
с seed-ключами, ESS и интервалами. Они выбраны после аудита как иллюстрации;
основные метрики рассчитаны по всем 500 запускам, без отбора удачных результатов.

Согласие людей и человеческая разметка здесь неприменимы: эталон вычисляется
точно на фиксированных известных оценках. Оценки пользователей не объявляются
полным знанием качества фильмов или причинного эффекта рекомендаций.

## Граница этапа

Код, данные аудита, базовая линия, неопределённость и конкретные случаи ошибок
подготовлены. Проверки слабого/нулевого покрытия, целенаправленный взлом, защита,
итоговый отчёт и презентация относятся к следующим этапам и здесь не выполнялись.
Критерий ненадёжности: RMSE >= 0.10 или не менее 5% запусков с неопределённой оценкой.
