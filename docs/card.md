# Карточка проекта К07 · logs

## Исследовательский вопрос
В каких случаях WIS на контрольном срезе MovieLens 1M существенно ошибается относительно точной ценности целевой политики при уменьшении покрытия её действий логирующей политикой?

## Данные и срез
MovieLens1M; K07-ML1M-25to34-v1: пользователи 25–34 лет с не менее чем 40 оценками. Основной срез — 1 696 пользователей и 383 928 оценок. Контроль — 150 полностью отложенных пользователей, по 20 фильмов на пользователя. Пользователи и фильмы выбраны воспроизводимо по SHA-256 без использования значений Rating.; лицензия: исследовательское использование; ПЕРЕРАСПРОСТРАНЕНИЕ ЗАПРЕЩЕНО

Популярность фильма определяется как число его оценок среди 1 546 разработочных пользователей; 150 контрольных пользователей из расчёта исключены. Для каждого контрольного пользователя его 20 фильмов сортируются по паре `(популярность, MovieID)`. Первые пять становятся целевыми, последние пять — популярными фильмами логирующей политики. Значения Rating в этом выборе не используются.

## Эталон и метод
Эталонный исход или прокси: 
Эталон пользователя — средняя бинарная награда его пяти целевых фильмов, где награда равна 1 при Rating >= 4. Всего имеется 150 × 5 = 750 целевых пар «пользователь — фильм»; у 357 из них Rating >= 4. Поэтому общая эталонная ценность равна `357 / 750 = 0.476`. Эталон не покрывает неоценённые фильмы, весь каталог и реальный причинный эффект рекомендации.

Оцениваемый оценщик: WIS — self-normalized importance sampling. Он оценивает целевую политику по созданному логирующей политикой логу и известным вероятностям действий.
Базовое сравнение: Основное сравнение — WIS при хорошем покрытии, epsilon = 0.5. Дополнительная проверка — наивная средняя награда в логе без коррекции на различие политик.

Пусть `T_u` — пять наименее популярных фильмов пользователя, а `B_u` — пять наиболее популярных. Целевая политика равномерна по `T_u`:

\[
\pi(a|u)=
\begin{cases}
1/5,& a\in T_u,\\
0,& \text{иначе}.
\end{cases}
\]

Логирующая политика является смесью равномерного выбора из всех 20 фильмов с весом epsilon и равномерного выбора из `B_u` с весом `1-epsilon`:

\[
\mu_\varepsilon(a|u)
=
\varepsilon/20
+
(1-\varepsilon)\mathbf{1}[a\in B_u]/5.
\]

Поэтому вероятность каждого целевого фильма равна `epsilon/20`, а вероятность выбрать любой из пяти целевых фильмов — `epsilon/4`. Для epsilon 0.5, 0.1, 0.02 и 0 эти вероятности равны соответственно 0.125, 0.025, 0.005 и 0. При epsilon = 0 поддержка целевых действий отсутствует и WIS не определён.

## Протокол симуляции

Один независимый запуск включает всех 150 контрольных пользователей. Для каждого пользователя генерируется 100 независимых рекомендаций с возвращением, поэтому один синтетический лог содержит 15 000 событий.

Для каждого значения `epsilon ∈ {0.5, 0.1, 0.02, 0}` выполняется 500 независимых симуляций. Всего получается 2 000 логов и 30 миллионов моделируемых событий. По каждому логу рассчитывается одно значение WIS.

Случайные seed фиксируются до основного эксперимента. Для каждого запуска сохраняются epsilon, seed, WIS, ESS, число целевых событий и число пользователей без целевых событий. Полные логи генерируются последовательно; для проверки сохраняется по одному примеру лога для каждого epsilon.

## Метрика и критерий
Метрика ошибки: RMSE оценки WIS относительно точной эталонной ценности по повторным симуляциям: квадратный корень из среднего квадрата разности между WIS и эталоном. Дополнительно считаются ESS, число целевых событий и доля запусков с нулевой суммой весов.

При нулевой сумме importance-весов WIS помечается как `undefined`: значение не заменяется нулём и не исключается без учёта. Доля неопределённых запусков сообщается отдельно. Для epsilon = 0 RMSE не рассчитывается, поскольку WIS математически не определён; это условие служит контролем нарушения поддержки.

Численный критерий успеха: RMSE достигает 0.10 или не менее 5% запусков дают неопределённую оценку. - уточнить у куратора.

## Риск и границы
Возможная ошибка оценщика: WIS может случайно показать значение рядом с эталоном при очень малом числе целевых событий. Результат также можно искусственно улучшить, если исключать неопределённые запуски, подбирать удачные seed или настраивать политики по контрольным оценкам.
За границами проекта: Не входят обучение моделей, сравнение WIS с IS и DR, второй датасет, неоценённые фильмы, реальный запуск рекомендаций, веб-интерфейс и выводы о качестве рекомендательной системы на всём каталоге MovieLens.
